# 独立した監査資料の閲覧と検証

この機能は、広聴AIのAPI、管理者アカウント、分析用Python環境がなくても、保存済みの資料を閲覧・検証するためのものです。検証の対象は手元にある資料です。原文の正しさ、公平性、記録されなかった実行の不存在、稼働モデルの重みを証明するものではありません。

## 機能と確認範囲

この配布物には、次の機能と検証用のテストを含みます。

- 単一HTMLで配布でき、ローカルファイルとして開いても動く監査ビューア。外部通信、CDN、解析用のサーバー、アクセス解析を必要としない。
- 既存の公開ZIPを読み込み、モデル、設定、処理状況、件数の範囲、除外項目を日本語で表示する。
- 2つの公開資料を比較し、確認した資料の識別子とツールの版を含む検査結果を保存・印刷できる。
- 分析コアから独立した検証コード、公開された形式仕様、正常・改変・欠落のテスト用資料を配布する。
- 形式、ファイルの集合、サイズ、ハッシュを検査する。不明な版、重複、パスの逸脱、過大な展開、埋め込みスクリプトを安全に扱う。
- 署名のない資料も読めるが、署名確認とは区別する。別経路で確認した公開鍵を使い、資料に同梱された鍵を自動的に信頼しない。
- 標準のJWS（ES256）を使った署名作成と独立検証。実際の鍵の発行・保管・失効管理や第三者サービスへの登録は行わない。
- 内部記録は明示的な別モードで開き、ハッシュ検査とサイズだけの検査を区別する。個人情報を外部へ送信せず、pickleなどの実行形式を読み込んで実行しない。
- 第三者へ渡せる静的な資料集を生成し、実行システムと無関係なWebサーバーやローカル媒体で配布できる。
- オフラインでのブラウザ動作、改変検出、信頼する鍵の違い、内部・公開の分離、画面幅・キーボード操作を検証する。

第三者による保管先の開設、インターネットへの公開、実運用鍵の作成、外部タイムスタンプサービスとの契約は、別途実施する運用作業です。署名時刻を自己申告することと、第三者による時刻証明は区別します。

## 資料を受け取った人の操作

配布用の `audit-viewer.zip` を展開し、ルートの `index.html` をブラウザで開きます。HTMLファイルだけを別の端末へコピーして使うこともできます。広聴AIへの接続やアカウントは不要です。「架空のサンプルを開く」で操作を試せます。

1. 「公開監査」を選び、「資料AのZIP」に公開監査資料を指定します。
2. 比較したい資料があれば「資料BのZIP」に指定します。比較結果は選んだ資料の違いであり、連続する実行履歴を保証しません。
3. 署名がある場合は「署名・別経路のハッシュを確認する」を開き、発行者と指紋を別の経路で確認した公開鍵を指定します。別途受け取ったZIPのSHA-256も照合できます。
4. 「資料を検査する」を押し、形式、元の記録との照合、受渡し用のハッシュ、署名をそれぞれ確認します。
5. 必要に応じて確認者のメモを記入し、「検査結果を保存」または「印刷・PDF保存」を使います。

検査結果には、資料のZIPハッシュ、実行ID、公開資料の識別子、検査した端末の日時、ツールの版・ビルド識別子が含まれます。日時は端末が申告した値であり、時刻証明ではありません。保存するJSONには監査原文を自動コピーしませんが、内部記録のファイル名や確認者が書いたメモに個人情報が含まれる可能性があります。

公開・内部のモード変更やファイル・公開鍵の変更時には、以前の検査結果とメモを消去し、再検査を求めます。「読み込んだ資料を消去」で画面内の資料と入力欄を消去できます。ブラウザストレージへの永続保存は行いません。利用者が保存したファイルやOSのメモリ管理まで消去する機能ではありません。

検査は別スレッドで実行します。「検査を中止」で停止でき、1つの資料の検査が120秒を超えた場合も停止します。中止した資料を確認済みとして表示せず、同じファイルで再検査できます。

## 表示の読み方

| 表示 | 確認したこと | 確認していないこと |
| --- | --- | --- |
| ハッシュ一致 | 元のマニフェストのハッシュと対象ファイルが一致 | マニフェスト自体の真実性 |
| サイズのみ一致 | 記録したバイト数と一致 | 同じ長さの別内容への置換 |
| 受渡し用の全ファイル一致 | 受渡し用マニフェストと全原本ファイルが一致 | 分析実行時から変わっていないこと |
| 選択した公開鍵と署名が一致 | 指定した公開鍵で受渡し用マニフェストの署名を検証 | 発行者の身元の確認、内容の正確性、署名時刻、現在の鍵の失効状態 |
| 別経路のZIPハッシュが一致 | 別途指定したハッシュとZIP全体が一致 | ハッシュを知らせた相手の信頼性 |

署名が一致しても、参照先のファイルが改変されていれば受渡し用のハッシュ検査に失敗します。この場合は確認済み資料として扱えません。署名なし・公開鍵なしの資料も閲覧できますが、署名確認済みとは表示しません。

現在の公開取り消し、最新版の有無、鍵の失効情報には問い合わせません。オフラインで検査した後、資料を引用・利用する時点の扱いは、公開元や監査者が示す最新の情報と別途照合してください。

## 内部記録を第三者が確認する

「内部監査」を明示的に選ぶと、原文を含む内部ZIPを開けます。この区分はデータの公開範囲を意味し、確認者を運用組織の職員に限定するものではありません。権限を持つ大学・研究者などへ、管理者APIキーを渡さず、必要なZIPを安全な媒体・保管先で提供できます。

ビューアでは全登録ファイルのハッシュまたはサイズを検査し、選択したJSON・CSV・テキストだけを表示します。テキストは最大2 MiBです。HTMLを含む文字列もテキストとして表示し、pickleや埋め込みを実行・復元しません。

原文への忠実性を確認する場合は、入力CSV、`after/args.csv`、`after/relations.csv`、`config.json`、`final_config.json` などを監査者が照合します。ビューアは公平性や誤抽出を自動判定しません。より大きいファイルや再集計は、監査者の管理する別のツールで扱ってください。内部資料を公開資料集へ含める操作は拒否します。

## 署名付き資料を作る

署名作成は、独立したNode.jsツールで行います。広聴AIのサーバーへの秘密鍵の登録は不要です。Node.js 22.17以降と、組織の手順で用意したECDSA P-256の署名鍵を使用します。鍵の自動生成・外部サービスへの登録は行いません。

```bash
node packages/audit-verifier/bin/audit-release.mjs sign public-audit.zip \
  --private-key signing-key.pem --output signed-public-audit.zip
```

暗号化したPKCS#8鍵では `--passphrase-file` を指定できます。指定ファイルのバイト列全体をパスフレーズとして読み取るため、不要な末尾改行を含めないでください。秘密鍵とパスフレーズファイルはアクセスを制限して管理し、資料集やビューアへ同梱しないでください。

内部記録には `--internal` を追加します。原本と元のマニフェストを変更せず、全ファイルをハッシュ化した `transfer.json` と、その署名である `signature.jws.json` を追加します。全項目・全値を個別にハッシュ化する方式ではありません。元のハッシュがないファイルも受渡し後の改変検査ができますが、過去の実行時点へ証拠を遡らせるものではありません。

既に署名・受渡し用情報がある資料への追加署名、欠落・不一致のある原本への署名、既存の出力ファイルへの上書きは拒否します。別の署名者で作成する場合は、保管した元のZIPから別ファイルを生成します。署名を作った時点での第三者時刻証明は付けません。

公開鍵はSPKI形式のPEMを使います。既存の署名鍵から取り出す場合の例です。

```bash
openssl pkey -in signing-key.pem -pubout -out public-key.pem
openssl pkey -pubin -in public-key.pem -outform DER | openssl dgst -sha256
```

この指紋を、資料とは別の信頼できる経路で確認者へ知らせます。ビューアに表示する `sha256:` の後ろの値と一致します。鍵の配布元・用途・管理者、交換・失効時の通知方法を決めて運用してください。オフラインで署名が一致しても、その鍵が現在有効だとは判断できません。

JWSの署名は受渡し用マニフェストの元のバイト列を対象にします。JSONを整形し直すと署名が一致しなくなるため、署名後は内容を加工せず配布します。仕様は同梱の `packages/audit-verifier/FORMAT.md` にあります。

## 運用者とは別の場所で保管・配布する

承認済みの公開資料を、大学や市民団体などが自分の保管先へ複製できます。次の操作はローカルの資料集を作るだけで、インターネットへ自動公開しません。

```bash
node packages/audit-verifier/bin/audit-release.mjs collect \
  signed-public-audit.zip another-signed-audit.zip \
  --public-key confirmed-public-key.pem \
  --viewer apps/audit-viewer/dist/index.html \
  --output public-audit-collection
```

署名なしの資料を保管する場合は `--public-key` を省略できます。指定した場合は、その鍵で署名を確認できる資料だけを受け入れます。公開ZIPの形式・ハッシュを検査してから、ZIPを元のバイト列のまま複製します。

資料集には一覧HTML、機械可読な `catalog.json`、各ZIP、独立ビューアを含めます。1回に最大100件・合計256 MiBです。既に存在する出力先は、空のディレクトリであっても使いません。一覧からZIPを保存し、ビューアで読み込めます。静的ファイルを配布できるWebサーバーや記録媒体で使え、広聴AIのAPIは不要です。

一覧に掲載するSHA-256だけでは配布元の身元を保証できません。第三者が保管する際は、受領したZIPのハッシュ、受領経路、確認した鍵の指紋を記録し、元の資料と照合できるようにします。記録が公開されたことと、すべての実行記録が提出されたことは別です。完全性を調べる監査には、権限を持つ第三者による別系統の実行記録・稼働環境との照合が必要です。

第三者へ複製すると、元のAPIで公開を取り消しても複製は消えません。公開対象の確認と、訂正・公開取り消しを複製先へ伝える方法を定めてから配布してください。内部記録や鍵の秘密情報を一般公開の保管先へ置かないでください。

## ビルド・再配布・検証

```bash
node apps/audit-viewer/build.mjs
node --test --experimental-test-isolation=none packages/audit-verifier/tests/*.test.mjs
node --test --experimental-test-isolation=none apps/audit-viewer/tests/*.test.mjs
```

ビルドは外部依存なしで行えます。`apps/audit-viewer/dist/index.html` は単一ファイルで動作し、`audit-viewer.zip` はソース、形式仕様、テスト、架空の資料、ライセンスを含みます。ソース・仕様・サンプルが同じなら同じHTMLと配布ZIPを生成します。外部CDN、フォントダウンロード、アクセス解析、サービスワーカーは使いません。CSPで通信と外部スクリプトを禁止します。

ブラウザテストには開発依存のPlaywrightとChromiumが必要です。検証ライブラリのテスト、署名作成、資料集の生成には追加パッケージもPythonも必要ありません。配布ZIP内のソースから再ビルドでき、第三者が検証コードを確認・変更できます。再配布時は同梱のライセンスに従ってください。

対応ブラウザにはWeb CryptoのECDSA P-256と `DecompressionStream("deflate-raw")` が必要です。実装時の確認対象はChromiumです。対応しない環境では検査を成功として表示せず、エラーを返します。HTMLを直接開くかHTTPSで配布してください。リモートのHTTPでは暗号機能が使えないことがあります。日本語フォントはOSのものを使います。

ZIPは保存・DEFLATE、UTF-8ファイル名の限定した形式に対応します。ZIP64、暗号化ZIP、ディレクトリエントリー、拡張フィールド、データ記述子、コメントを含む一般的な再圧縮ZIPには対応しません。既存の監査エクスポーターが生成したZIPをそのまま使ってください。未対応の版・形式、重複、不正なパス、破損、サイズ上限超過は拒否します。
